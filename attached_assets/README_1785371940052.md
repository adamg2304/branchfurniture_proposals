# Dynamic Quote MVP — template wiring

David's HTML, wired so a server fills in the data. The page reads **only** from
`window.QUOTE` — no quote data, rep, rates, or SKU images are hardcoded anymore.

## Files
- **`quote-template.html`** — the page. Renders header, line items, live totals,
  White Glove breakdown, terms, and the accept + clickwrap e-sign flow.
- **`quote-sample.js`** — a `window.QUOTE` blob with the real Chai Travel numbers.
  Dev-only (lets you open the HTML in a browser standalone). Also the **contract**
  for what the Cloud Run service builds from HubSpot — field sources are in the header.

## Open it locally
Open `quote-template.html` in a browser. It loads `quote-sample.js` and renders the
Chai Travel quote. Verified: base totals match the source quote to the penny
(subtotal $15,233.00 · WG $2,484.95 · discount −$1,218.64 · tax $1,464.31 · **total $17,963.62**).

## What changed from David's original
1. **Single injection point.** The hardcoded `tiers` / `ADDONS` / `TILE` consts are gone.
   Everything reads from `window.QUOTE`.
2. **One option, no tier switcher.** Per the call — render the actual quote off its
   line items. Tiers are a V2 decision (still open: where tier membership lives).
3. **Discount row added** to the summary (was missing; shows only when > 0).
4. **Values shown verbatim.** For an unmodified quote, WG / discount / tax display
   exactly as quoted (`wgAmount`, `discount`, `taxAmount`). Only if the client edits a
   quantity do WG and tax recompute from the quoted rates so the live UX still works —
   the availability-check banner tells client + rep to reconfirm in that case.
5. **Image tiles hyperlink to Shopify** via each line item's `productUrl` (`hs_url` field),
   with the SKU-library `imageUrl`. Falls back to a line drawing if either is missing.
6. **Accept POST stubbed** — `submitAccept()` posts to `meta.acceptUrl` with the signature
   audit payload. Wire the real endpoint + token when the service is up.

## Cloud Run handoff (server side, not built here)
A single Cloud Run **service** (request/response, not a Job):

- `GET /q/{quoteId}-{token}`
  1. Validate token (store it on the quote or in Airtable — don't trust the sequential quote #).
  2. Fetch deal → associated quote → line items + contact + company + owner
     (same v4 associations single-fetch used for the QBO estimate flow, read-only).
  3. Build the `window.QUOTE` object (shape = `quote-sample.js`), mapping:
     - line item unit price/qty → `items[].price/qty`, quoted qty → `orig`
     - SKU → `imageUrl` from the image library, `hs_url` → `productUrl`
     - WG line → `wgAmount` (+ ratio → `wgRate`), discount → `discount`,
       tax → `taxAmount` (+ ratio → `taxRate`)
  4. Inject it **inline** before the render script and serve the HTML.
     (Replace the `<script src="quote-sample.js">` line with `<script>window.QUOTE = {…}</script>`.)
     Token + HubSpot private-app token stay server-side; the browser never calls HubSpot.

- `POST /q/{quoteId}/accept`
  - Record signature (name, timestamp) + server-captured IP & user-agent (audit trail).
  - Fire the Zapier webhook (same webhook-payload pattern as the delivery-order flows) →
    HubSpot status update + note/engagement with the audit trail, optional stage move.

Secrets in Secret Manager, not the image. Prototype/deploy straight to Cloud Run (skip Replit).

## Deliberately cut for the MVP
Tiers (good/better/best), synced comments, add-ons beyond what's already in the line items,
and signature-grade signing (DocuSign/PandaDoc) — all V2. Clickwrap here is the documented V1;
confirm the acceptance language with whoever owns contracts before treating it as binding.
